# Lenses

Named research modes for `@ledgeindex/profile`. Each lens picks relevant URLs from the crawl catalog, fetches pages, and synthesizes **typed JSON** output (with citations).

## Setup

```ts
import {
  researchLensIds,
  getResearchLens,
  getLensDefinition,
  defaultProfileLenses,
  parseResearchLensList,
  PROFILE_MODE_ID,
} from "@ledgeindex/profile";
```

## Usage — defaults

```ts
const lenses = defaultProfileLenses();
// all 14 built-in lenses (see table below)
```

Pass a subset when you only need part of a profile:

```ts
await profileSite("https://example.com/", [
  "identity",
  "capabilities",
  "package_usage_examples",
]);
```

## Usage — from CLI / env strings

```ts
const lenses = parseResearchLensList(
  "identity,pricing,package_primitives_usage,package_usage_examples",
);
```

## Usage — introspect

```ts
for (const id of researchLensIds) {
  const def = getLensDefinition(id);
  console.log(id, def.label);
}

const lens = getResearchLens("capabilities");
```

## Built-in lenses (14)

### Company & market

| Id | Label | Output focus |
|----|-------|----------------|
| `identity` | Positioning & ICP | Category, one-liner, buyers, segments |
| `pricing` | Pricing | Plans, price text, trial / enterprise signals |
| `capabilities` | Product & features | Ranked capabilities (`main` / `top` / `supporting`) |
| `integrations` | Integrations | Third-party tools, connectors, channels |
| `trust` | Trust & security | Compliance, security, privacy claims |
| `gtm` | Go-to-market | Sales motion, CTAs, trial/demo/signup |
| `business_usage` | Business usage | Business problems → what teams build/run (not feature list) |
| `content_seo_strategy` | Content & SEO strategy | Content pillars, URL patterns, organic discovery plays |

### Docs & developer experience

| Id | Label | Output focus |
|----|-------|----------------|
| `docs_identity` | About | What a **docs set** covers (kind, language, summary) |
| `ai_and_dev_experience` | AI & developer experience | APIs, SDKs, MCP, docs integration for builders |
| `basic_usage` | Basic usage | Quickstarts, hello-world, install paths |
| `main_use_cases` | Main use cases | Primary product scenarios (ranked for example catalogs) |

### Package library / builder workflows

| Id | Label | Output focus |
|----|-------|----------------|
| `package_primitives_usage` | Package primitives | Core APIs / building blocks and how to use them |
| `package_usage_examples` | Package guides & examples | Concrete tutorials, recipes, templates with code paths |

Use **`package_primitives_usage`** + **`package_usage_examples`** when feeding **planner / builder workflows** or a Package Library — primitives for API moves, examples for full guided scenarios.

### Priority badges

Several lenses tag items as `main`, `top`, or `supporting` (capabilities, main_use_cases, business_usage, package lenses, content_seo_strategy). The UI and downstream agents use these to surface pillars first.

## Typed outputs

Per-lens TypeScript types: `IdentityLensOutput`, `DocsIdentityLensOutput`, `CapabilitiesLensOutput`, `PackageUsageExamplesLensOutput`, …

Merged profile shape: `CompanyProfileData` / `LensOutputById`.

## Example — company profile

```ts
import { profileSite, parseResearchLensList } from "@ledgeindex/profile";

const modes = parseResearchLensList("identity,capabilities,pricing,gtm");

const { profile } = await profileSite("https://example.com/", modes);
console.log(profile.identity);
console.log(profile.capabilities);
```

## Example — docs / builder research

```ts
const { profile } = await profileSite("https://docs.example.com/", [
  "docs_identity",
  "basic_usage",
  "package_primitives_usage",
  "package_usage_examples",
]);

console.log(profile.docs_identity);
console.log(profile.package_usage_examples);
```
