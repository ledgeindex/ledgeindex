# Site research

`@ledgeindex/profile` — structured research briefs for a website: crawl once, run **lenses** (identity, pricing, capabilities, package guides, …). See [Lenses](/reference/profile/lenses) for all 14 built-in modes.

## When to use profile

Use `@ledgeindex/profile` when the goal is open-ended site understanding with fixed output shapes. You name the lenses; the package decides which pages matter and how to fill the schema.

Use [Crawl & retrieval](/docs/core) when you need a durable searchable index for RAG, not a one-pass research profile. Use [HTTP server](/docs/server) when you want profile HTTP routes (`/api/profile/*`) beside docs ingest.

## Quickstart

```ts
import { profileSite } from "@ledgeindex/profile";

const { profile } = await profileSite("https://example.com/", [
  "identity",
  "capabilities",
]);

console.log(profile.identity);
console.log(profile.capabilities);
```

`profile` is an alias of `profileSite`.

Install:

```bash
npm i @ledgeindex/profile
```

What runs under the hood:

1. Build a crawl catalog of the site
2. Per lens: pick URLs → fetch → synthesize structured output
3. Optionally expose landscape / competitor runs over HTTP when mounted on the server

## Use your profile

Pass lens ids (or use defaults). Options control model, page budget, and pick-only dry runs:

```ts
import { profileSite, defaultProfileLenses } from "@ledgeindex/profile";

const result = await profileSite("https://example.com/", defaultProfileLenses(), {
  modelId: "…",
  maxPages: 40,
  sitemapOnly: false,
  pickOnly: false,
  onLensStart: (lens, index, total) => {
    console.log(`lens ${index + 1}/${total}: ${lens}`);
  },
});
```

Mount on the server:

```ts
import { createLedgeIndexServer } from "@ledgeindex/server";

await createLedgeIndexServer({
  profiles: ["docs", "profile"],
});
```

With the `profile` slot enabled:

- `GET /api/profile/health`
- `POST /api/profile/runs` — landscape run (`EXA_API_KEY`)
- `GET /api/profile/runs/:id`
