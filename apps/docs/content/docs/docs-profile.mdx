# Sources, chat & MCP

The **`@ledgeindex/docs`** package — what powers web, desktop, and the SDK. You add a docs URL or repo, crawl/index it, ask questions with citations, and expose the same index to agents via MCP.

## When to use it

Use `@ledgeindex/docs` when you want documentation you can chat with or expose to an agent. Add a source, crawl it, ask questions, connect MCP if you need it.

| You want… | Use |
|-----------|-----|
| Terminal or a Node script, no server | [SDK](/guides/setup-sdk) or [CLI](/guides/setup-cli) |
| A browser UI plus API | [Set up web](/guides/setup-web) |
| An API you already have running | [@ledgeindex/client](/reference/client) |
| Your own Fastify host | [Server](/docs/server) with `profiles: ["docs"]` |

Skip this package if you only need crawl, chunk, and embed functions with no sources model. That is [@ledgeindex/core](/docs/core).

Skip it if you want structured site research (pricing, positioning, package guides) instead of a searchable index. That is [@ledgeindex/profile](/docs/profile).

## What it includes

- Sources you can create, update, and delete (personal or global)
- Crawl and ingest with progress, cancel, and resume
- Refresh when the upstream docs change
- Source chat with citations
- MCP over HTTP for Cursor, Claude Desktop, and other clients

## Running it

**With a server.** Enable the docs profile on `@ledgeindex/server`:

```ts
profiles: ["docs"]
```

See [Server](/docs/server).

**Without a server.** The SDK and CLI bundle this package in-process. See [Guides](/guides).

API details: [@ledgeindex/docs](/reference/docs-runtime). Route list: [HTTP API](/reference/api).

## HTTP routes

Full tables live in the [HTTP API reference](/reference/api). Short map:

| Area | Examples |
|------|----------|
| Sources | `GET/POST /api/sources`, source detail |
| Ingest | `POST /api/sources/:id/ingest/start`, progress, cancel, resume |
| Refresh | `/api/sources/:id/refresh/*` |
| Chat | `POST /api/sources/:id/ask`, `/chat/docsAgent` ([chat API](/reference/api/chat)) |
| MCP | Path from `GET /health`; OAuth under `/.well-known/*` ([health & MCP](/reference/api/health)) |
| Health | `/health`, `/health/packages`, `/health/db` |

After boot, `GET /health` shows the MCP path and whether the docs profile loaded.

## Auth (optional)

Local dev and the desktop sidecar default to `LEDGEINDEX_AUTH_REQUIRED=0`, so you do not need sign-in. Set `LEDGEINDEX_AUTH_REQUIRED=1` and add your host auth plugin when `/api/*` routes should require a token. See [HTTP API auth](/reference/api/auth) and [Set up web](/guides/setup-web).
