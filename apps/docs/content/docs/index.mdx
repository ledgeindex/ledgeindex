# Docs overview

LedgeIndex turns **documentation websites** into indexed knowledge **agents** can query: crawl a docs URL, extract and chunk the pages, embed them in a vector index, and **ask questions that come back with citations** to real pages. You can run that flow from a terminal, a Node script, a browser UI, or an MCP client in Cursor or Claude Desktop.

On top of indexing, LedgeIndex also does **site research profiles** — structured JSON about a company or docs set (positioning, pricing, capabilities, package guides, and more) via [14 built-in lenses](/reference/profile/lenses). Profile output is separate from the search index: one job is “what does this site say, in typed fields?”; the other is “search and chat over everything we crawled.”

**New here?** Start with **[SDK](/docs/sdk)** (Node, no server) or **[Guides](/guides)** for step-by-step setup. The sections below are for composing lower-level packages yourself.

## What is available

**Indexing & chat**

- **Web crawl** — discover URLs (sitemap, links), extract markdown, optional LLM URL filter and example enrichment
- **Vector search + rerank** — local FastEmbed + LibSQL by default; Postgres + Gemini for a cloud-like stack
- **Source chat (RAG)** — query rewrite, retrieval, coverage check, agent answer with chunk citations
- **Example catalog** — optional ingest step for code samples and setup blocks (feeds planner/builder workflows)

**Research & agents**

- **Profile lenses** — crawl once, run lenses (identity, pricing, `package_usage_examples`, …)
- **MCP** — `list_source_sets`, `get_source_set`, `ask_source` when an API is running (`/mcp`)

## Ways to run (no custom server)

The simplest paths do not use `@ledgeindex/server`:

| Surface | Package | Docs |
|---------|---------|------|
| Node scripts / CI (**start here**) | `@ledgeindex/sdk` | [SDK](/docs/sdk) · [Set up SDK](/guides/setup-sdk) |
| Terminal | `ledgeindex` | [CLI](/docs/cli) · [Set up CLI](/guides/setup-cli) |

Both use FastEmbed + LibSQL by default, store data under `~/.ledgeindex/data`, and run crawl without a model key. Ask, profile, and optional crawl AI features need a chat provider key.

## What ships in the monorepo

LedgeIndex is open-core: published **`@ledgeindex/*`** packages, first-party **apps**, and **hosts** that wire the server.

- **Packages** — `@ledgeindex/core`, `docs`, `profile`, `server`, `sdk`, `client`, … (currently **0.1.9**)
- **Web & desktop** — browser UI, Electron app, this docs site, Expo mobile ([overview](/docs/apps))
- **Hosts** — `hosts/api` (`:3010`, MCP at `/mcp`), `hosts/desktop-server` (`:3015`)

Typical local dev ports: API **3010**, web **3004**, docs site **3005**.

## Pipeline (concept)

```text
discover → extract → enrich → chunk → embed → store → query
                                      │
                                      ├─ markdown chunks → retrieve / chat
                                      └─ example chunks → queryExamples
```

## Quickstart (library)

Prefer no custom server code? Use [CLI](/guides/setup-cli) or [SDK](/guides/setup-sdk) instead of the snippet below.

```bash
npm i @ledgeindex/core @ledgeindex/docs @ledgeindex/profile @ledgeindex/server
```

```ts
import { startLedgeIndexServer } from "@ledgeindex/server";

await startLedgeIndexServer({
  profiles: ["docs", "profile"],
  port: 3010,
  host: "127.0.0.1",
});
```
