# Self-host the API

**Want crawl/ask without writing server code?** Use [CLI](/docs/cli), [SDK](/docs/sdk), or [Guides](/guides).

This page is for **running `startLedgeIndexServer` in your own process** — a custom Fastify host, a worker, or hacking on the monorepo.

## Packages

| Package | Role |
|---------|------|
| `@ledgeindex/core` | Crawl, extract, enrich, chunk, embed, query |
| `@ledgeindex/repo` | Git checkout index, AST chunking, clone — [reference](/reference/repo) |
| `@ledgeindex/docs` | Sources, indexing, chat, MCP — powers web/desktop/SDK | [Sources, chat & MCP](/docs/docs-profile) |
| `@ledgeindex/profile` | Site research lenses (`profileSite`) |
| `@ledgeindex/server` | Fastify host wiring docs + profile routes |
| `@ledgeindex/sdk` | In-process crawl, ask, profile — **no server** ([guide](/guides/setup-sdk)) |
| `@ledgeindex/client` | HTTP client when an API is already running ([reference](/reference/client)) |

For a decision tree (CLI vs web vs MCP vs core-only), see [Guides → When to use what](/guides#when-to-use-what).

## Install (npm)

```bash
npm i @ledgeindex/core @ledgeindex/docs @ledgeindex/profile @ledgeindex/server
```

Monorepo development: clone [ledgeindex/ledgeindex](https://github.com/ledgeindex/ledgeindex), `npm install` from the repo root.

## First server

```ts
import { startLedgeIndexServer } from "@ledgeindex/server";

await startLedgeIndexServer({
  profiles: ["docs", "profile"],
  port: 3010,
  host: "127.0.0.1",
});
```

Confirm with `GET /health/packages` (versions and active profiles).

The in-repo dev host is `hosts/api` (`npm run dev:api`). For the full web UI stack, use [Set up web](/guides/setup-web).

## Environment (API process)

Minimal local `.env`:

```bash
LEDGEINDEX_PROFILES=docs,profile
PORT=3010
LEDGEINDEX_AUTH_REQUIRED=0
LEDGEINDEX_DATA_DIR=./.data
```

You need at least one chat/embed provider key for ingest and chat (`GOOGLE_GENERATIVE_AI_API_KEY`, `OPENAI_API_KEY`, or `DEEPSEEK_API_KEY`). Optional: `COHERE_API_KEY` (rerank), `LEDGEINDEX_VECTOR_BACKEND=libsql|pgvector`, `POSTGRES_CONNECTION_STRING` for pgvector.

`LEDGEINDEX_PROFILES` is parsed by the host and passed to `createLedgeIndexServer({ profiles })`. Legacy value `company` maps to `profile`.

For local development, keep **`LEDGEINDEX_AUTH_REQUIRED=0`** unless you are testing your own auth integration.

## Composition vs products

| Approach | When |
|----------|------|
| Call **core** primitives in your own pipeline | You control every step (discover, chunk, store, query) |
| Use **profile** (`profileSite` or SDK `runProfile`) | Structured site research, not a searchable doc index |
| Run **server** with `docs` profile | Deployable API: sources, ingest, chat, MCP |
| Use **SDK / CLI** | Scripts and CI — no HTTP, no UI |
